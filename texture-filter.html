纹理过滤与 mipmap：一个像素到底该取哪个纹素

纹理不是「把图贴上去」那么简单：屏幕一个像素可能只覆盖半个纹素（放大），也可能盖住几十个纹素（缩小）。 放大用 magFilter 插值，缩小靠 minFilter + mipmap 先选层再插值。 这页把两组过滤器和 mip 链都摊开给你看。

1. 同一张贴图，为什么远处会"沸腾"

  1. 地面铺的是一张 256×256 的棋盘格，格子里还画了 2 像素宽的细边 —— 高频内容。
  2. UV 按世界坐标每 8 个单位重复一次，所以 1 个纹素只有 0.031 个世界单位宽。
  3. 近处：一个像素盖不到 1 个纹素 → 放大，取最近点会看到方块（锯齿）。
  4. 远处：一个像素盖住 几十个纹素 → 缩小。如果只从第 0 层取 4 个样，就会把高频内容混叠成随相机移动而闪动的噪声。

mipmap 就是预先算好的一串逐级缩小一半的图，一共 N+1 层，总显存只多约 1/3。 缩小的时候先在链上选一层（或两层混合），再从那一层里取 4 个样。

2. 两组过滤器，管的是两件不同的事

minFilter: NEAREST | LINEAR                      ← 缩小、且只用第 0 层
           NEAREST_MIPMAP_NEAREST | LINEAR_MIPMAP_NEAREST   ← 选一层，层内 NEAREST/LINEAR
           NEAREST_MIPMAP_LINEAR  | LINEAR_MIPMAP_LINEAR    ← 选两层再线性混合（三线性）
magFilter: NEAREST | LINEAR                      ← 放大，只作用在第 0 层

缩小一共三种组合方式：不跨层（可能闪烁）、跨层但不混合（层与层交界处会有可见的"台阶"）、 跨层且混合（LINEAR_MIPMAP_LINEAR，代价是 8 次取样，质量最好）。

各向异性过滤（EXT_texture_filter_anisotropic）解决的是另一种情况： 地面被压得很扁时，一个像素在 UV 上的形状是细长条而不是正方形， 各向同性 mipmap 只能按长边降分辨率 → 结果糊。这个扩展在浏览器里要主动查，不是核心特性，本页不依赖它。

3. 最容易踩的坑：纹理"不完整"

  1. WebGL2 里 MIN_FILTER 的默认值是 NEAREST_MIPMAP_LINEAR，也就是「需要 mipmap」。
  2. 如果你上传完贴图没有 generateMipmap，这条 mip 链就是空的。
  3. 此时纹理被判为 incomplete，采样不会报错，而是静默返回黑色（准确说是 (0,0,0,1)）。
  4. 顺带一提：非 2 的幂尺寸在 WebGL2 里完全合法，照样能生成 mipmap —— WebGL1 的限制已经取消了。

把下面的「生成 mipmap」关掉、同时 minFilter 保持带 mipmap 的那种，就能看到整块地面变黑。 这就是为什么现实中大部分「贴图是黑的」都跟这一条有关。

顺带一个更隐蔽的坑：「不调用 generateMipmap」并不会把已经生成的 mip 层删掉 —— 它们还留在纹理对象里，纹理依然是完整的，画面不会有任何变化。 要真正复现「漏了 generateMipmap」，必须重新上传 level 0（或换一个纹理对象）。 所以这个页面在切换开关时是重建纹理的，而不是「这次跳过那一行」。
