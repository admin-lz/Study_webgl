0. 高度场缩略图（CPU 同一函数）

和左边画面用的是同一个 terrainH(x,z)。
小图里能直接看出：域扭曲把等高线拧弯、山脊把波峰收成刀背、台阶把斜坡切成层岩。
蓝线是水位 —— 山是"露出水面的那部分"。

1. 噪声：一个 hash 加一次插值

// 值噪声：格子顶点各给一个 0~1 的随机数，再平滑插值
float hash21(ivec2 p) {                       // 整数 hash，GPU / CPU 逐位一致
  uint h = (uint(p.x) * 73856093u) ^ (uint(p.y) * 19349663u);
  h ^= h >> 13; h *= 0x85ebca6bu; h ^= h >> 16;
  return float(h & 0xFFFFFFu) / 16777216.0;
}
float vnoise(vec2 p) {
  vec2 i = floor(p), f = fract(p);
  vec2 u = f * f * (3.0 - 2.0 * f);           // smoothstep：一阶导连续 → 没有方格棱
  float a = hash21(ivec2(i)),               b = hash21(ivec2(i) + ivec2(1, 0));
  float c = hash21(ivec2(i) + ivec2(0,1)),  d = hash21(ivec2(i) + ivec2(1, 1));
  return mix(mix(a, b, u.x), mix(c, d, u.x), u.y) * 2.0 - 1.0;
}
  1. 关键在插值函数。 用 f 线性插值会露出方格；smoothstep 让导数连续，才看不出格子。 梯度噪声（Perlin）则是在格点上放随机梯度向量、和偏移向量点乘，再用五次曲线插值 —— 对比"值噪声"切一下就能看出高频细节更干净。
  2. hash 要能两边复现。 这里用整数位运算而不是 fract(sin(dot(...))*43758.5)， 因为后者在 GPU（float32）和 CPU（float64）上结果会飘 —— 一旦 CPU 和 GPU 结果不一致， 预计算的属性和着色器算的高度就会"打架"，山谷里长出两套山。

2. fBm：把无穷细节塞进有限三角函数

sum = 0; norm = 0; amp = 1; q = p;
for (int o = 0; o < 8; o++) {
  if (o >= u_oct) break;
  float n = noise(q);
  float v = (u_shape == 0) ? n :                    // fBm
            (u_shape == 1) ? 1.0 - 2.0 * abs(n) :   // 山脊：|n| 处成尖峰
                             2.0 * abs(n) - 1.0;     // 丘峦
  sum += v * amp; norm += amp;
  q *= u_lac;        // 每层频率 ×2
  amp *= u_gain;     // 每层振幅 ×0.5
}
float h = sum / norm;                                // 归一化，免得层数一改整体高度就变
h *= 0.35 + 0.9 * (noise(p * 0.13) * 0.5 + 0.5);     // 低频"大陆"调制：平原 / 山脉分区
  1. 间隙度 > 衰减的倒数 才收敛。频率 ×2、振幅 ×0.5 时总振幅收敛到 2 倍基础振幅。 把衰减调到 0.7 会"糊"（高频占了太多能量），调到 0.3 又太光滑 —— 这两个滑块就是给你感受这个的。
  2. 山脊 = 1-|n|。把噪声在 0 处翻转，普通噪声的平滑过零点变成尖峰，叠起来就是刀刃状山脊。 真实地形生成里通常再按高度加权（高的地方更 ridged），这里为了看清效果就先一刀切。
  3. 域扭曲：用噪声本身去偏移采样坐标 p += noise(p) * warp。代价是每层多 2 次求值， 换来的是"被侵蚀过"的弯曲河道感 —— 视频里那种"随手一调就像真山"基本都靠它。

3. 法线：对高度函数求导，不是对三角形求

vec3 terrainN(vec2 p, float e) {
  float hL = terrainH(p - vec2(e, 0.0));
  float hR = terrainH(p + vec2(e, 0.0));
  float hD = terrainH(p - vec2(0.0, e));
  float hU = terrainH(p + vec2(0.0, e));
  return normalize(vec3(hL - hR, 2.0 * e, hD - hU));   // (-dh/dx, 1, -dh/dz)
}
  1. 为什么不从三角形算法线？ 面法线是分片的，山会变成一堆折面；而且 LOD 一换， 同一块地形的着色就会跳变。对高度函数求导则连续、和网格密度无关 —— 低模也是光滑的。
  2. 代价是 4 次额外求值，也就是每顶点 5 次（高度 1 + 法线 4）。读数里会算给你看： 8 层 fBm 就是每顶点约 200 次 hash。
  3. 步长 e 要跟着网格走。 这里取当前 LOD 的格距： 粗网格配小步长只会抖出一堆高频噪点。真想保住细节，就得再叠一张法线贴图 —— 这也是地形着色器的常规做法。
  4. CPU 预计算版顺手用网格邻居算中心差分（不必再多 4 次求值），所以它比 GPU 版便宜 —— 但代价是 LOD 换了、分辨率变了，法线就固定住了。切到 CPU 模式还能看到"改一个参数要重算全图"的卡顿。

4. 分块 LOD：裂缝从哪来，怎么缝

  1. 块 = 索引缓冲的一段。 一整张 129×129 顶点缓冲不动，按 LOD 级别另建索引： 级别 L 只取全分辨率网格里"每隔 2^L 个"的顶点。所以几何数据只有一份，切 LOD 就是换索引。 （索引按"块"排序，每块连续 → 每块一次 drawElements，代价是绘制调用从 1 涨到 64。）
  2. 级别选择 + 平滑。 按块中心到相机的距离取 log2， 再反复扫描把相邻块的高差压到 ≤1 —— 差 2 级时"取中点"就缝不平了，这是硬约束。
  3. 裂缝的本质是 T 型接点。 细块的边上有中点顶点，粗块的边是直线， 两边的高度不一样 → 细看是一条能看穿的缝。把细块边上的中点吸附到粗块那条直线上 （用高度函数的两个端点值取平均，因为中点正好在半程），缝就精确闭合了 —— 因为高度是解析函数， 两个端点一插值就是粗块直边的表达式。取消勾选"缝合"就能看到这条缝。
  4. 工业界的其他解法： 裙边（每块四周往下拉一圈"墙"，便宜、但陡坡要拉很长）、 CLOD/CDLOD 的顶点形变（把裂缝摊到整块上，看不出跳变）、几何 clipmap（环形网格跟着相机走）。 共同点都是"别让两块用不同的采样率直接相连"。
