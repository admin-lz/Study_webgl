纹理数组：一次 draw 上百种贴图，还不会串色

要给场景里每个物体一张不同的贴图，最直接的办法是"每画一个换一次 bindTexture"。 想省掉切换就要合并成大图（图集），但图集在 mipmap 上会出事：相邻格子的颜色会互相渗进来。 纹理数组是第三选择 —— 一个纹理对象里有 N 层，每层有自己独立的 mip 链。

1. 三种做法的取舍

  1. 逐层 bindTexture：每画一个物体换一次绑定。CPU 侧开销大（驱动要校验/翻译状态）， 但最直观，且每张图可以有自己的尺寸和格式。
  2. 图集（atlas）：合并成一张大图，一次绑定画完所有。省状态切换， 但要求所有图格式一致、尺寸可以不规则（要自己打包），而且 mip 会跨格子采样 —— 需要给每格留 padding 并把边缘像素铺出去。
  3. 纹理数组：一个纹理对象装 N 层，采样是 texture(sampler2DArray, vec3(u, v, layer))。 每层独立 mip、独立 wrap，物理上不可能串色；代价是所有层必须同尺寸同格式，且层数有上限。

2. 代码：只差一行

// 上传：一次 texStorage3D 定规格，再逐层 texSubImage3D
gl.texStorage3D(gl.TEXTURE_2D_ARRAY, levels, gl.RGBA8, 64, 64, layers);
for (let i = 0; i < layers; i++)
  gl.texSubImage3D(gl.TEXTURE_2D_ARRAY, 0, 0, 0, i, 64, 64, 1,
                   gl.RGBA, gl.UNSIGNED_BYTE, pixelsForLayer(i));
gl.generateMipmap(gl.TEXTURE_2D_ARRAY);

// 采样
uniform sampler2DArray u_tex;
vec4 c = texture(u_tex, vec3(uv, float(layer)));   // ← 比 sampler2D 多一个 layer

注意 texImage3D 的最后一维是 层数 1（一次传一层），深度维度才是层的下标。 这个参数顺序（width, height, depth, x, y, z）是初学时最容易写反的地方。

3. 什么时候该用它

  1. 材质变体很多、尺寸一致：地表贴图、角色皮肤、UI 图标集 —— 一次 draw 里按 layer 取。
  2. 体渲染 / 切片数据：本来就是 3D 数据，TEXTURE_3D 更合适；但如果是"一叠 2D 图"且要各自 wrap，数组更好。
  3. 阴影 / 反射的多张 RT：级联阴影的每一级、立方体阴影贴图（WebGL2 里常直接用 TEXTURE_CUBE_MAP_ARRAY）。
  4. 不适用：尺寸不一、需要各自 mip 偏置以外的独立 wrap、或者层数超过 MAX_ARRAY_TEXTURE_LAYERS。
