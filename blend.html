混合与透明：为什么半透明要关深度写入、还要排序

深度测试只能回答「谁挡住谁」，回答不了「两层半透明怎么叠」。这一页把 混合方程、绘制顺序、深度写入 三个开关拆开，让你亲手把画面弄坏。 alpha 混合不可交换，这是全部麻烦的源头。

1. 混合在算什么

片元颜色 × srcFactor + 已有像素 × dstFactor → 新像素
  1. 不透明靠深度测试决定「谁留下」；半透明要靠混合把两层颜色加起来。
  2. enable(BLEND) 之后，片元不再覆盖，而是和帧缓冲里已有的颜色按系数混合。
  3. 最常用的 blendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)，就是再入门的「over」算子。
  4. 关键在于：新像素同时依赖旧像素。所以 A 叠 B 和 B 叠 A 结果不一样。

gl.depthMask(false) 管的是「要不要写深度」，和 enable(DEPTH_TEST) 的「要不要比深度」是两件事。

2. 透明的三个坑

  1. 排序：必须从远到近画。但「远」是按物体算的，两个互相穿插的面板根本没有正确顺序。
  2. 深度写入：半透明关掉 depthMask。否则先画的那层把深度占了，后面更远的层直接被扔掉，混不出来。
  3. 加色例外：blendFunc(ONE, ONE) 是 dst += src，加法可交换 —— 加色混合不需要排序。

这句要补一个前提：不发生过曝截断时才严格可交换。 8 位颜色缓冲在亮部会截到 1.0，一截断顺序就又有影响了 —— 实测只有千分之几的像素有差别，但确实存在。

这就是为什么火焰、光晕用加色，而玻璃、水必须排序。

3. 本页真正在跑的核心

// ① 不透明：写深度，不混合
gl.disable(gl.BLEND);
gl.depthMask(true);
drawOpaque();

// ② 半透明：按远到近排序，关掉深度写入
gl.enable(gl.BLEND);
gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA);
gl.depthMask(false);          // 只比深度，不写深度
for (const pane of sortedFarToNear) {
  draw(pane);
}

// 换混合模式只改这两个系数：
//   加色  blendFunc(SRC_ALPHA, ONE)        ← 可交换，不用排序
//   乘色  blendFunc(DST_COLOR, ZERO)
//   预乘  blendFunc(ONE,       ONE_MINUS_SRC_ALPHA)

注意 排序 + 深度写入开着也能对（先画远的，后面的都更近，能通过测试）。 但这是「碰巧对」—— 一旦有两个互相穿插的面板，按物体排序就失效了，深度写入会把真正该看见的层剔掉。

4. 对照着拧开关看

  1. 关掉「混合」：面板变实心，后画的直接盖住先画的 —— 退回画家算法。
  2. 开着混合和排序，勾上「深度写入」：看起来还行（碰巧对），但换成加色模式再关排序就露馅。
  3. 勾上「深度写入」并关掉「排序」：最近的面板占了深度，后面的整个消失，重叠区变纯色。
  4. 关掉「排序」用 alpha 模式，等相机转到另一侧：颜色叠加顺序反了，混出来的色偏了。
  5. 切到「加色」再关排序：画面不变。因为加法可交换，这是加色的最大便利。
  6. 切到「乘色」：规律相反，越叠越暗，连背景都被乘掉。
