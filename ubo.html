UBO：把 uniform 打包成一块显存，一次上传多次复用

uniform 的问题是"每个 program 一组、每次 draw 都可能要传一遍"。UBO 把一组 uniform 变成一块可以共享的缓冲： 传一次，多个 draw call、多个 program 都能读。代价是你要接受 std140 的排版规则 —— 结构体不是紧凑排列的。

1. 为什么 uniform 不够用

  1. 普通 uniform 是挂在 program 上的：换 program 要重传，同一个值给两个 program 要传两次。 场景里几百个 draw call 都用到同一个相机矩阵时，这就是白白的 API 开销。
  2. UBO 是一块缓冲，绑到某个 binding point，program 通过 block 索引去读。 一次 bufferSubData，所有读这块的 program 同时看到新值。
  3. 还有"每一批 draw 之间只改变量"的场景：把 per-draw 数据放进一个 UBO 数组， bindBufferRange 换个偏移就能切换 —— 比逐个 uniform* 快得多。

2. std140 的坑（本页重点）

struct Obj {
  vec4  color;   // byte 0   （vec4 对齐 16）
  vec3  offset;  // byte 16  （vec3 也对齐 16！所以不能塞在 12）
  float scale;   // byte 28  （float 对齐 4，可以紧跟 vec3 后面）
  vec2  uvOff;   // byte 32  （vec2 对齐 8）
  // → 结构体自身对齐 = 16，所以 size 会被向上补齐到 48
};
  1. 这不是可选项。std140 规定：vec3 / vec4 按 16 字节对齐，数组元素的 stride 也要按 16 取整 —— 所以 vec3 后面永远有 4 字节空洞。
  2. CPU 端写数据时必须按同样的规则排。搞错了不会报错，只会读到错位的值（比如颜色里混进了 scale）—— 本页第一个下拉框就是干这个的，切到"紧凑 32 字节"能立刻看到画面崩掉。
  3. 省字节的两个办法：把 vec3 + float 打包成 vec4（本页第三个选项）， 或者用 std430（只在 SSBO / compute 里能用，规则更宽松）。
  4. 查询 gl.getActiveUniformBlockParameter(..., UNIFORM_BLOCK_DATA_SIZE) 可以拿到驱动算出的真实大小， 别硬编码 —— 但布局规则还是得自己守。

3. API 三句话

const ubo = gl.createBuffer();
gl.bindBuffer(gl.UNIFORM_BUFFER, ubo);
gl.bufferData(gl.UNIFORM_BUFFER, bytes, gl.DYNAMIC_DRAW);

const idx = gl.getUniformBlockIndex(prog, "Camera");
gl.uniformBlockBinding(prog, idx, 0);            // program 侧：这块绑到 0 号槽
gl.bindBufferBase(gl.UNIFORM_BUFFER, 0, ubo);    // 全局侧：0 号槽 = 这块缓冲

每个 program 都要做一次 uniformBlockBinding（告诉它"你的第几号块读第几个槽"）， 之后只要绑槽位就行。槽位数量有上限（MAX_UNIFORM_BUFFER_BINDINGS，一般 12~36 个）， 所以是"槽位复用"而不是"每块一个槽"。
