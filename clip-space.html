裁剪空间与透视除法：w 到底存了什么

gl_Position 输出的不是屏幕坐标，而是裁剪空间坐标。 这一步的 x/y/z 都还没除以 w —— 真正的"近大远小"发生在 GPU 拿到你的顶点之后，那个除法里。 这一页把 local → 世界 → 观察 → 裁剪 → NDC → 像素 整条链路拆开看。

深度精度：为什么 near 调小一点点，远处的深度就废了

1. 一次变换的完整链路

vec4 clip = P * V * M * vec4(local, 1.0);   // gl_Position
vec3 ndc  = clip.xyz / clip.w;              // 透视除法（GPU 自动做）
vec2 px   = (ndc.xy * 0.5 + 0.5) * viewportSize;
depth     = ndc.z * 0.5 + 0.5;              // 写进深度缓冲的值
  1. w 就是"眼睛到点的距离"的替身。透视投影矩阵把观察空间的 z_view 塞进了 clip.w， 所以除以 w 就等于"按距离缩小" —— 近大远小不是单独一步，它就是这次除法。
  2. 正交投影的 w 恒为 1，除法等于没除。这就是正交"没有透视感"的根本原因。
  3. 裁剪发生在除法之前。GPU 拿 clip 坐标去和 -w ≤ x,y,z ≤ w 这个立方体求交。 为什么不在 NDC 里裁？因为 w 可能是 0 或负数（点在相机背后），除法会得到翻转的坐标， 得到的"多边形"完全是错的。先裁掉，再除，就不会遇到 w ≤ 0。
