Raymarching：不写一个三角形，用"距离场 + 步进"画东西

光栅化是"把三角形投影到屏幕"；raymarching 反过来 —— 对每个像素发一条射线，反复问同一个问题： 离最近的表面还有多远？ 如果场景能回答这个问题（SDF，符号距离场），就能一路"安全地"跳过去。 曲面求交、软阴影、环境光遮蔽、描边，全都是同一条射线上的副产品。

1. 核心循环只有 6 行

float t = 0.0;                     // 沿射线已经走了多远
for (int i = 0; i < STEPS; i++) {
  vec3 p = ro + rd * t;
  float d = map(p);                // 到最近表面的距离
  if (d < EPS) { hit = true; break; }   // 撞上了
  t += d;                          // ← 走了 d 一定不会穿过任何表面
  if (t > FAR) break;              // 跑出场景
}
  1. 为什么可以"跳"？ SDF 的定义保证：以 p 为中心、半径 d 的球内一定没有表面。 所以沿射线推进 d 是绝对安全的 —— 这也是它比"固定小步长"快得多的原因。
  2. 它会慢在哪？ 射线贴着表面掠过时（掠射角），d 会变得极小，被迫用很多步一点点挪。 热力图模式下能看到：轮廓边缘和地面远处全是"深色/高步数"。
  3. EPS 与 FAR 的取舍： EPS 太大 → 表面出现"缺口"和气泡；太小 → 步数暴涨。 这是 raymarching 最典型的调参体验。

2. 法线、软阴影、AO 都是副产品

// 法线：对 SDF 做中心差分（不用求导公式）
vec3 n = normalize(vec3(
  map(p + vec3(e,0,0)) - map(p - vec3(e,0,0)),
  map(p + vec3(0,e,0)) - map(p - vec3(0,e,0)),
  map(p + vec3(0,0,e)) - map(p - vec3(0,0,e))));

// 软阴影：往光源方向再走一遍，记录"擦过表面"的最小程度
float res = 1.0;
for (...) { float h = map(ro + rd*t); res = min(res, k*h/t); t += h; }

// AO：沿法线抬升采样，看 SDF 涨得多快（涨得慢 = 周围有遮挡）
occ += (h - map(p + n*h)) * sca;

注意这三件事都复用了同一个 map()，不需要阴影贴图、不需要法线贴图、不需要额外的几何 pass。 代价是像素级的重复计算：本页每像素最多 几百次 map() —— 这也是为什么 raymarching 只适合中小场景。

3. 什么时候值得用

  1. 体积 / 程序化场景：云、雾、火焰、噪波地形 —— 本来就没有三角面，SDF 是天然表示。
  2. 超远距离 / 无限细节：分形（Mandelbulb）、无限重复的走廊。三角形数量会爆炸，SDF 不会。
  3. 光滑融合：smooth-min 让两个物体的接缝自然过渡，用多边形做要重新拓扑。
  4. 不适合：角色、大量独立物体、需要真实材质贴图和动画（骨骼）的场景。 工业界更常见的是混合方案：光栅化 + 局部 raymarching（比如屏幕空间反射、体积光）。
