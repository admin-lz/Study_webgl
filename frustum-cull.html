视锥剔除：怎么把"看不见的东西"在提交前就扔掉

剔除不是"少画几个像素"，而是少几次 draw call、少几万个顶点的顶点着色器。 这一页把视锥的 6 个平面抽出来，拿三种包围体去测，实时告诉你各留下多少对象。 红色 = 被剔除，绿色 = 完全在视锥内，黄色 = 和平面相交（保守保留，可能是误留）。

完全在视锥内 与平面相交 → 保守保留 被剔除

1. 平面从哪来

// 视锥的 6 个面可以"免费"从 viewProj 矩阵里读出来（Gribb-Hartmann）
// m 的第 4 行 = w 行，第 1~3 行 = x/y/z 行
左面：  row4 + row1    右面：row4 − row1
下面：  row4 + row2    上面：row4 − row2
近面：  row4 + row3    远面：row4 − row3
// 归一化之后，(n, d) 满足：n·p + d > 0 表示 p 在面的正面（内侧）
  1. 推导思路：-w ≤ x ≤ w 就是两个平面 x + w ≥ 0 和 -x + w ≥ 0。 而 x、w 都是 (x,y,z,1) 的线性函数，系数正好是矩阵的行 —— 所以平面直接"长在矩阵里"。
  2. 这就是为什么很多引擎不存"视锥六面"，而是在变换完之后现抽 —— 反正矩阵就在手上。

点测试最省，但对象一大就会"贴脸消失"；球体便宜且旋转无关，代价是方盒子会多留一些； AABB 更贴合盒子（误留少），但要在每个面上挑"最靠外的那个顶点"，比球贵一点。

3. 面试要点

  1. 剔除一定是保守的：宁可多画，不可少画。平面测试只会产生假阳性（留在视锥外的对象）， 永远不会假阴性 —— 一旦漏掉，画面就会突然缺一块。
  2. 平面测试不是精确裁剪：一个巨大的物体横跨整个视锥、本身在相机后面， 它和 6 个平面都"相交"，于是被保留 —— 这是设计如此。想更精确只能做层级细分（BVH/八叉树）。
  3. 包围球 vs AABB 的取舍：球对旋转不变（不用重算），AABB 对轴向对齐物体更紧。 实际引擎往往两个都存：宽相用球，窄相用 AABB。
  4. 顺序要先粗后细：先按距离/层级粗筛（一个 BVH 节点没进就整棵子树跳过）， 再对剩下的做平面测试。逐对象测 6 个平面是 O(n)，层级化之后接近 O(log n + 可见数)。
  5. 别只剔除"看不见"，还要降级：视锥剔除之后还有遮挡剔除、LOD、距离剔除（far clip）。 面试里能说出"剔除是为了省顶点处理和 draw call，不是为了省像素"是加分项。
