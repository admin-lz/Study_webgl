后处理链：几何只画一遍，剩下的全靠一串全屏 pass

环境光遮蔽（SSAO）和泛光（Bloom）都是屏幕空间的：不去改几何、不去加灯光， 只拿已经渲染好的深度 / 法线 / 颜色，再"过一遍"。本页把整条链的中间缓冲全部摊开给你看 —— 深度、噪点 AO、模糊后的 AO、亮部、各级 Bloom，切一下下拉框就能看到每一级长什么样。

1. 整条链：几何只画一遍，剩下全是全屏 pass

几何 pass   → 颜色(RT0) + 视图法线(RT1) + 深度纹理      ← 只画一遍
SSAO        → 深度 + 法线 → 半球采样 → 噪点 AO          ┐
AO 模糊     → 4×4 box（噪点必须糊掉，否则一动就沙沙响）  │
亮部提取    → 颜色 → 阈值 → 半分辨率                     │
模糊 H / V  → 可分离高斯，窄半径一轮                     │ 共 10 趟
模糊 H / V  → 再叠一轮宽半径（"多级"就是这么来的）        │ 全屏
降采样 1/4  → 再模糊 H / V → 大范围晕                    │
合成        → 颜色 × AO + Bloom × 强度 → ACES → gamma    ┘

后处理没有几何，只有"纹理进、纹理出"。所以现代管线里 RT 的格式和数量（带宽）比 shader 里那几行算术更值钱： 这 10 趟全屏 pass，每趟都要把整屏读一遍写一遍。半分辨率做 Bloom 就是因为这一步最容易被带宽卡住。 切"显示"挨个看中间缓冲，比盯着最终画面猜有用得多。

2. SSAO：用手边的深度和法线凑出"角落变暗"

vec3 P = viewPosFromDepth(uv);            // 反投影：拿深度还原视图空间位置
vec3 N = viewNormalFromRT1(uv);           // 法线不重算，几何 pass 顺手写进 RT1
mat3 TBN = randomBasis(N, gl_FragCoord);  // 每像素随机转一下，噪点变成白噪声才能被糊掉
for (int i = 0; i < 16; i++) {
  if (i >= u_samples) break;
  vec3 sp = P + TBN * u_kernel[i] * u_radius;
  vec2 suv = project(sp);
  float sceneZ = viewZ(texture(u_depth, suv).r);
  float range = smoothstep(0.0, 1.0, u_radius / abs(P.z - sceneZ));  // 挡住"远处的高墙"误判
  occ += (sceneZ >= sp.z + bias ? 1.0 : 0.0) * range;
}
ao = pow(clamp(1.0 - occ / float(u_samples), 0.0, 1.0), u_pow);
  1. 它是"假"的遮蔽。 屏幕外的东西一概不知道，物体边缘会把背景算成遮挡（halo）。 所以工程上都会限制半径、做范围检测、或者干脆把 AO 只用在近处。
  2. 为什么要随机旋转？ 固定 12 个方向会在每个像素上留下同样的条纹；随机转一下变成白噪声，4×4 模糊就能抹掉。 代价是"噪点 → 模糊"必然糊掉细节，所以半径不能太大。
  3. 法线从哪来。 本页是几何 pass 用 MRT 顺手写出来的。也可以省掉它、用 dFdx/dFdy 对位置求导算法线， 省一张 RT，但物体轮廓处法线是错的 —— 这就是经典取舍。

3. Bloom：亮的地方"漏"到周围

  1. 阈值提取：只保留超过阈值的部分（max(c - threshold, 0)，软的用 smoothstep）。 阈值太低 → 整个画面发灰；太高 → 只有最强的光源发光。
  2. 可分离高斯：二维高斯 = 先横着卷一遍、再竖着卷一遍，N² 变 2N。这是后处理里最常用的一招。
  3. 多级叠加：小半径 + 大半径叠在一起才像真的泛光。做法就是降采样到 1/4 再来一轮 —— 降采样本身就是"放大 kernel"，还顺带省了一大截带宽。
  4. 顺序：先 AO 再 Bloom。AO 是"减光"、Bloom 是"加光"，先减后加才能让暗角里的高光也正常发光； 反过来的话，AO 会把 Bloom 的辉光一起压暗。
