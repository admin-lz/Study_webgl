骨骼蒙皮：顶点是怎么"跟着骨头走"的

蒙皮的本质只有三步：把顶点绑到骨头上（bind）、算出每根骨头的当前变换（animation）、 用权重把几根骨头的变换混起来（skinning）。这一页把这三步拆开跑，并且对比 "每个顶点只跟一根骨头"（刚性绑定）和"跟多根骨头"（线性混合蒙皮 LBS）的差别。

1. 三步：绑定 → 求变换 → 混合

// 1. 绑定（美术阶段一次性做）：把顶点从"模型空间"换算到"骨骼局部空间"
inverseBind[i] = inverse( 绑定姿势下第 i 根骨头的世界矩阵 )

// 2. 动画：自顶向下累乘出每根骨头的当前世界矩阵
global[i] = global[parent] * local[i]

// 3. 蒙皮矩阵（每帧、每根骨头一个）
skin[i] = global[i] * inverseBind[i]

// 4. 顶点：加权混合（4 根骨头足够，GPU 一次算完）
p' = Σ  w_k * skin[index_k] * p          Σ w_k = 1
  1. 为什么要有 inverseBind：顶点存的是模型空间坐标，而 skin 矩阵要作用在"骨骼空间"。 先乘 inverseBind 把顶点搬回骨骼的局部坐标系，再乘 global 搬到现在的位置。 绑定姿势一变（比如重新绑骨），inverseBind 就得重算。
  2. 每根骨头 4 个矩阵？不是 —— 每根骨头一个 mat4，用 uniform 数组 （uniform mat4 u_bones[N]）或者纹理/UBO 传上去。 移动端骨头多了会撞 uniform 上限，所以常见做法是把骨骼矩阵打进一张浮点纹理。
  3. 索引和权重是顶点属性：一般是 uvec4（或 float 转 int）+ vec4 权重， 权重在导出时就归一化好，运行时不用再除以总和。

2. 为什么会有"糖纸"和关节塌陷

  1. LBS 是线性混合矩阵：把两个旋转矩阵按权重加起来，得到的一般不再是旋转矩阵 （会带缩放/切变）。这就是肘部旋转时体积塌陷、贴图扭成"糖纸"的来源。
  2. 想缓解就得用 双四元数蒙皮（DQS）：混合的是四元数而不是矩阵，能保住体积； 代价是每个顶点多几次乘法，且要处理符号（和 slerp 一样，需要先统一半球）。
  3. 只跟一根骨头（刚性绑定）不会塌陷，但关节处会出现硬折角 —— 把上面的"权重"切过去就能看到区别。
  4. 法线也要蒙皮：用同一个混合矩阵的 3×3 部分变换法线；如果骨骼带非均匀缩放，记得用逆转置。

3. 面试要点

  1. CPU 每帧只算 N 根骨头的矩阵（N 通常几十），顶点变换全在顶点着色器里做 —— 这是蒙皮便宜的原因。
  2. 顶点属性里骨头索引用整数类型（vertexAttribIPointer），别用浮点数做索引，会有精度和转换问题。
  3. 和四元数的关系：骨骼的 local 变换一般存成 (位置, 四元数, 缩放)，运行时再拼成矩阵； 插值在四元数域做，拼矩阵只在最后一刻做。
  4. 进阶名词：GPU skinning（顶点着色器里做，本页）、CPU skinning（老式，浪费带宽）、 morph target / blend shape（和蒙皮叠加使用）、compute shader skinning（把结果写进 VBO 给后面的 pass 用）。
