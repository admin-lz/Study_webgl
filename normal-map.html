法线贴图：不增加三角形，只改"这一点的朝向"

高模的细节能不能贴到低模上？能 —— 因为光照只关心法线。 法线贴图把每个像素的法线存进一张 RGB 图（切线空间），着色时用 TBN 矩阵转回世界空间。 这一页把高度场、法线贴图、TBN 三者的关系摊开看。

1. 为什么存的是"切线空间"的法线

  1. 同一张砖墙法线贴图要能贴到任何朝向的面上。如果直接存世界空间法线，转个角度就全错了。
  2. 所以贴图里存的是相对于表面自己的坐标系：x 沿 u 方向，y 沿 v 方向，z 沿表面法线。
  3. 平坦表面的法线是 (0,0,1)，编码成颜色就是 (0.5, 0.5, 1.0) —— 所以法线贴图整体偏蓝紫色。
  4. 着色时用 TBN = [T, B, N] 把它转回世界空间：N_world = normalize(TBN * n_tangent)。
vec3 n = texture(u_nrmMap, uv).xyz * 2.0 - 1.0;  // [0,1] → [-1,1]
n.xy *= u_strength;                              // 强度，只缩放切向分量
vec3 N = normalize(TBN * normalize(n));

本页的 UV 是 (x/SPAN, -z/SPAN)，所以 T = +X，B = −Z，N = T × B = +Y。 这个对应关系必须和贴图生成时一致，否则凸起会变成凹陷（光照看着"反了"）。

2. 切线从哪来：顶点属性 vs 屏幕导数

  1. 顶点切线：建模时算好 T、B 存进顶点属性（本页每个顶点只存一份，因为 UV 是均匀的）。
  2. 屏幕导数：不存切线，用 dFdx/dFdy 在片元里反解出来 —— 只要知道位置和 UV 在屏幕上怎么变，就能解出 T、B。
  3. 两者在平面上完全等价（可以切着看，画面一模一样）。
  4. 但一旦顶点被位移（displacement）顶起来，UV 算出来的固定切线就跟不上真实起伏了，导数法会自动跟上。
vec3 dp1 = dFdx(v_world), dp2 = dFdy(v_world);
vec2 du1 = dFdx(v_uv),    du2 = dFdy(v_uv);
float det = du1.x * du2.y - du2.x * du1.y;
vec3 T = (dp1 * du2.y - dp2 * du1.y) / det;
vec3 B = (dp2 * du1.x - dp1 * du2.x) / det;

导数法的代价是不能在顶点着色器里用，而且三角形退化（UV 面积为零）时 det 会趋近 0，必须兜底。

3. 法线贴图不是位移

  1. 法线贴图只改着色：轮廓还是低模的轮廓，边缘不会多出任何凹凸。
  2. 打开「位移」才是真的把高度加到顶点上 —— 轮廓会变，但需要足够密的网格，而且开销是真的。
  3. 想要"看起来很立体但不用高模"的中间态，还有视差贴图 / 视差遮蔽（POM），代价是在片元里反复采样。

本页把高度值塞进了法线贴图的 alpha 通道（"显示高度场"那一档直接读 .a）。 真实项目也常这么打包：RG = 法线 xy，B = 法线 z，A = AO 或高度，一张图当两张用。
