上万实例：一次 draw，用 gl_InstanceID 当 pick id

一万个立方体不是循环一万次 draw。位置放在实例缓冲里， drawElementsInstanced(..., 10000) 一次画完。 ID 趟同样一次 draw：gl_InstanceID + 1 拆进 RGB。对照：逐物体 GPU pick。

1. 为什么能撑上万

1 个立方体 mesh N 份 offset 1 次 instanced draw gl_InstanceID → RGB readPixels 1px
  1. CPU 只上传一份顶点 + 一份 N×vec3 位置。JS 不再按物体循环 draw。
  2. VS 里 a_offset 的 divisor=1：每个实例换一个平移，顶点还是那 24 个。
  3. GPU 自动把 gl_InstanceID 编成 0…N−1。Pick 用 id = gl_InstanceID + 1（0 留给背景）。
  4. 屏幕一趟、ID 一趟，各 1 次 draw。上一课 6 个物体是 6 次。

上万个简单盒子，CPU AABB 仍然可以很快。本页要看的是：GPU pick 只有合批 / 实例化之后，才不会被一万次 API 调用拖死。

100×100 = 10000 个实例 · 移动鼠标拾取 · 拖动旋转相机

把鼠标移进画布。

2. 本页真正在跑的核心

// VS：每个实例自动拿到 0,1,2,… 
int id = gl_InstanceID + 1;
v_idColor = vec3(
  float(id & 255) / 255.0,
  float((id >> 8) & 255) / 255.0,
  float((id >> 16) & 255) / 255.0
);
world = a_pos * size + a_offset;   // a_offset 每实例一份

vertexAttribDivisor(a_offset, 1);
drawElementsInstanced(TRIANGLES, cubeIndexCount, UNSIGNED_SHORT, 0, 10000);

// 和上一课一样读 1 个像素
readPixels(px, py, 1, 1, RGBA, UNSIGNED_BYTE, pixel);
const i = R + G*256 + B*65536 - 1;   // gl_InstanceID
const model = models[i];             // 业务对象，和 offsets 下标对齐

不要在 JS 里按物体循环画 ID。像素里只有整数下标，真正的 node-行-列 在 models[i]。

3. 对照着看

  1. 提示里的 model.id 来自 JS 的 models[i]，不是像素里的字符串。
  2. 打开浏览器 GPU 计时：每帧屏幕 1 次 + pick 1 次，不会出现一万次 draw。
  3. 上一课每个物体一次 drawElements，到上万就会卡在 CPU 提交，不在求交。
