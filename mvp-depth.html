MVP 与深度：两个立方体为什么一个能挡住另一个

三角形那一课，顶点直接写在裁剪空间，所以看不见矩阵。 这一课补上两件事：MVP 把物体从局部坐标送到屏幕，以及 深度缓冲按距离决定遮挡，而不是谁后画谁赢。

1. 顶点怎么变成像素坐标

局部 a_pos × Model 世界 × View 相机 × Projection 裁剪空间 gl_Position
  1. M 模型：这个立方体自己的平移 / 旋转 / 缩放。两个立方体 mesh 相同，只是 M 不同。
  2. V 视图：把整个世界搬到「相机在原点、朝 −Z」。拖动画布改的就是 V。
  3. P 投影：透视（近大远小）或正交（远近一样大），同时把深度写进 gl_Position.z。

着色器里只有一行：gl_Position = u_mvp * vec4(a_pos, 1.0)， 其中 u_mvp = P × V × M（列向量，右乘）。GPU 再做一次除以 w，才到 −1~1 的 NDC。

2. 深度测试在比什么

  1. 每个像素除了颜色，还有一份 gl_FragCoord.z（近 0，远 1）。
  2. enable(DEPTH_TEST) 之后：新片元更近才留下，更远的扔掉。
  3. 关掉它，GPU 就是油漆工：后 draw 的覆盖先 draw 的，不管谁离相机更近。
  4. 每帧必须 clear(COLOR_BUFFER_BIT | DEPTH_BUFFER_BIT)，否则上一帧的深度还在。

先勾掉「深度测试」，再切换绘制顺序，错误遮挡会立刻出现。

橙色 = 近立方体　 蓝色 = 远立方体　 拖动旋转相机

3. 本页真正在跑的核心

// 同一个立方体 mesh，两套 Model
const modelNear = translate(identity(), -0.15, 0.45,  1.05);
const modelFar  = mul(translate(identity(), 0.10, 0.70, -0.80), scaleMat(1.4, 1.4, 1.4));

const view = lookAt(eye, [0, 0.5, 0], [0, 1, 0]);
const proj = perspective(fov, aspect, 0.1, 50);
// mvp = P * V * M
const mvp = mul(mul(proj, view), model);

gl.enable(gl.DEPTH_TEST);                       // 可关掉对比
gl.clear(gl.COLOR_BUFFER_BIT | gl.DEPTH_BUFFER_BIT);
gl.uniformMatrix4fv(uMvp, false, mvp);
gl.drawElements(gl.TRIANGLES, count, gl.UNSIGNED_SHORT, 0);

后面 texture.html / sphere.html 的相机就是这一套。 多物体时每画一个就换一次它的 M，V 和 P 通常整帧共用。

4. 对照着拧开关看

  1. 深度开、先远后近 / 先近后远：画面应该一样，橙色始终在前。
  2. 深度关、先近后远：蓝色会把橙色涂掉。这就是「没有深度」。
  3. 勾上「用灰度看深度」：越黑越近。透视下远处被挤在一片亮里，深度不是线性距离。
  4. 勾上「正交」：远近一样大。那就是 P 被拿掉透视之后的样子。
  5. 深度开着，取消「每帧清深度」，再拖相机：破洞 / 残影来自上一帧的 z。
  6. 拉 FOV：只改 P。拖画布：只改 V。两个立方体相对位置来自各自的 M。
